# Space Apps Glossary

## NASA Space Apps Challenge-এর প্রয়োজনীয় শব্দের বাংলা ব্যাখ্যা

> **এটি একটি সহায়ক glossary; NASA-র official dictionary বা rulebook নয়।** একই শব্দের অর্থ discipline, dataset বা challenge অনুযায়ী বদলাতে পারে। Technical requirement, data definition, judging term ও legal meaning-এর ক্ষেত্রে সংশ্লিষ্ট বছরের official Challenge Statement, metadata, guide ও Terms-কে অগ্রাধিকার দিন।

## কীভাবে ব্যবহার করবেন

- English শব্দটি খুঁজে তার সহজ বাংলা ব্যাখ্যা পড়ুন।
- শব্দটি কোনো dataset বা challenge-এ নির্দিষ্ট অর্থে ব্যবহৃত হলে সেই পৃষ্ঠার definition দেখুন।
- “সমার্থক” শব্দ সবসময় পুরোপুরি interchangeable নয়; বাংলা ব্যাখ্যা ধারণা বোঝানোর জন্য।
- নিচের সংক্ষিপ্ত তালিকা [A–Z Index](#a-z-index)-এও সাজানো আছে।

## ১. NASA Space Apps, hackathon ও event

| শব্দ | সহজ বাংলা ব্যাখ্যা |
|---|---|
| **Access** | কোনো data বা service দেখা, query করা বা download করার সুযোগ; এটি reuse permission বা licence-এর সমান নয়। |
| **Award** | নির্দিষ্ট judging প্রক্রিয়ায় স্বীকৃতি বা পুরস্কার। Award category, যোগ্যতা ও ঘোষণা প্রতি বছরের guide থেকে যাচাই করতে হয়। |
| **Challenge** | NASA বা partner-এর দেওয়া সমস্যা/প্রশ্ন, যেটি সমাধান করতে participant-দের আমন্ত্রণ জানানো হয়। |
| **Challenge card / summary** | Challenge-এর তালিকায় দেখা সংক্ষিপ্ত পরিচিতি। এটি সাধারণত full statement-এর বিকল্প নয়। |
| **Challenge Statement** | Challenge-এর পূর্ণ বিবরণ: সমস্যা, লক্ষ্য, background, resource, constraint ও expected output থাকতে পারে। |
| **Code of Conduct** | অংশগ্রহণকারীদের সম্মানজনক, নিরাপদ ও অন্তর্ভুক্তিমূলক আচরণের নির্দেশনা। |
| **Global Judging** | NASA Space Apps-এর global পর্যায়ে project মূল্যায়নের প্রক্রিয়া। যোগ্যতা ও পদ্ধতি current-year guide-এ দেখতে হয়। |
| **Global Organizing (GO) Team** | NASA Space Apps-এর বৈশ্বিক আয়োজন ও participant support-সংশ্লিষ্ট organizing team। |
| **Hackathon** | নির্দিষ্ট সময়ের collaborative event, যেখানে দল সমস্যা নিয়ে কাজ করে prototype, analysis, design বা অন্য deliverable তৈরি করে। |
| **Honorable Mention** | কোনো edition-এ দেওয়া recognition category হতে পারে; নাম, সংখ্যা ও শর্ত বছরভেদে যাচাই করতে হবে। |
| **Local Event** | কোনো শহর/অঞ্চলের organizer বা Local Lead পরিচালিত Space Apps event; onsite বা virtual হতে পারে। |
| **Local Lead** | Local Event-এর organizer/contact, যিনি স্থানীয় schedule, venue ও logistics সম্পর্কে সাহায্য করেন। |
| **Mentor** | অভিজ্ঞ ব্যক্তি, যিনি ধারণা, domain বা technical কাজে পরামর্শ দেন; তিনি team-এর কাজের মালিক নন। |
| **Participant Guide** | registration, team formation, submission বা judging-এর কোনো ধাপ বোঝানো official সহায়ক নির্দেশিকা। |
| **Participant Terms & Conditions** | অংশগ্রহণের শর্ত—যেমন eligibility, consent, submission, rights ও responsibility। |
| **Project Submission Guide** | project page/form-এ কীভাবে project জমা দিতে হবে তার বছরের নির্দিষ্ট নির্দেশনা। |
| **Universal Event** | NASA Space Apps-এর virtual global participation option; format, team rules ও schedule current-year FAQ-তে যাচাই করুন। |
| **Global Nominee / Finalist / Winner** | নির্দিষ্ট বছরের judging/award প্রক্রিয়ার পর্যায় বা স্বীকৃতি; criteria ও announcement current guide-এ দেখুন। |
| **Event** | নির্দিষ্ট তারিখ, সময় ও format-এ হওয়া আয়োজন; schedule ও deadline official event page-এ যাচাই করতে হয়। |

## ২. Project idea, product ও design

| শব্দ | সহজ বাংলা ব্যাখ্যা |
|---|---|
| **Audience** | Project-এর presentation, story বা information যাদের জন্য তৈরি। |
| **Feature** | Project-এর কোনো নির্দিষ্ট কাজ বা ক্ষমতা; যেমন map filter বা data summary। |
| **Impact** | Project কীভাবে user, community, research বা decision-এ উপকার করতে পারে—প্রমাণ ও সীমা-সহ বর্ণনা। |
| **Iteration** | Feedback বা test-এর পর project-এর কোনো অংশ আবার উন্নত করার ধাপ। |
| **MVP (Minimum Viable Product/Prototype)** | সবচেয়ে ছোট কার্যকর version, যা project-এর core idea বা user journey দেখায়। |
| **Persona** | সম্ভাব্য user-কে বোঝানোর কাল্পনিক কিন্তু evidence-informed profile; বাস্তব user research-এর বিকল্প নয়। |
| **Problem statement** | কোন user-এর কোন সমস্যা কেন গুরুত্বপূর্ণ—তার সংক্ষিপ্ত বর্ণনা। |
| **Prototype** | ধারণা পরীক্ষা বা demo করার প্রাথমিক model/app/design; এটি পূর্ণাঙ্গ production product নাও হতে পারে। |
| **Scope** | নির্দিষ্ট event window-তে project-এ কী থাকবে এবং কী থাকবে না—তার সীমা। |
| **Success criteria** | কাজ সফল হয়েছে কি না বোঝার আগে থেকে নির্ধারিত, যাচাইযোগ্য শর্ত। |
| **User** | Project-এর output ব্যবহার করে কোনো কাজ করবেন, তথ্য জানবেন বা সিদ্ধান্তে সহায়তা পাবেন—এমন ব্যক্তি/গোষ্ঠী। |
| **User journey** | User-এর প্রয়োজন থেকে শুরু করে input, interaction ও ফলাফল পর্যন্ত ধাপের বর্ণনা। |
| **User story** | User-এর দৃষ্টিকোণ থেকে একটি প্রয়োজন: “আমি [user], [লক্ষ্য] করতে চাই, যাতে [কারণ]।” |
| **Wireframe** | Interface-এর প্রাথমিক layout sketch; সাধারণত রং ও visual polish-এর আগে screen-এর কাঠামো দেখায়। |

## ৩. Teamwork, planning ও presentation

| শব্দ | সহজ বাংলা ব্যাখ্যা |
|---|---|
| **Acceptance criteria** | কোনো task বা feature complete বলতে কী দেখা/পরীক্ষা করতে হবে—তার নির্দিষ্ট তালিকা। |
| **Backup / fallback** | মূল data, API, presenter বা demo ব্যর্থ হলে ব্যবহারের বিকল্প পদ্ধতি। |
| **Blocker** | এমন বাধা যার কারণে গুরুত্বপূর্ণ কাজ এগোচ্ছে না। |
| **Brainstorming** | সম্ভাব্য idea দ্রুত সংগ্রহের আলোচনা; পরে idea-গুলো যাচাই ও বাছাই করতে হয়। |
| **Collaboration** | সদস্যদের মধ্যে তথ্য, দক্ষতা ও কাজ ভাগ করে যৌথভাবে project তৈরি। |
| **Deliverable** | Challenge বা submission-এ দেখানোর/জমা দেওয়ার project output; সুনির্দিষ্ট তালিকা statement ও guide-এ থাকে। |
| **Dependency** | অন্য কোনো task, software, service বা data-এর ওপর কাজটি নির্ভরশীল। |
| **Demo** | Project-এর কোনো কাজ live, recorded বা sample দিয়ে দেখানো। Demo format event-এর নিয়মে নির্ধারিত হতে পারে। |
| **Handoff** | এক speaker বা কাজের owner থেকে অন্যজনের কাছে পরিষ্কারভাবে দায়িত্ব/আলোচনা এগিয়ে দেওয়া। |
| **Milestone** | Project-এর গুরুত্বপূর্ণ checkpoint—যেমন প্রথম end-to-end demo বা final submission। |
| **Pitch** | অল্প সময়ে problem, user, solution, data ও evidence বোঝানোর উপস্থাপনা। |
| **Q&A (Questions and Answers)** | উপস্থাপনার পর প্রশ্ন ও উত্তর পর্ব। |
| **Risk register** | সম্ভাব্য ঝুঁকি, প্রভাব, owner ও fallback-এর তালিকা। |
| **Sprint** | নির্দিষ্ট কাজ ও checkpoint-সহ ছোট development period; এখানে planning পদ্ধতি, official NASA rule নয়। |
| **Task board** | কাজ, owner, status ও dependency দেখানো shared তালিকা/board। |
| **Team role** | Team-এর কোনো কাজের দায়িত্ব—যেমন data, design, code, testing বা submission। |
| **Time zone** | পৃথিবীর অঞ্চলভেদে ব্যবহৃত স্থানীয় সময়; event deadline বোঝার সময় zone-সহ সময় লিখতে হয়। |

## ৪. Data ও science

| শব্দ | সহজ বাংলা ব্যাখ্যা |
|---|---|
| **API (Application Programming Interface)** | নির্দিষ্ট নিয়মে software-কে অন্য service থেকে data বা function চাইতে দেওয়া interface। |
| **Archive** | দীর্ঘমেয়াদে data সংরক্ষণ, catalog ও access দেওয়ার ব্যবস্থা। |
| **Attribute / field** | Table বা feature-এর বর্ণনামূলক তথ্যের ঘর; যেমন date, class বা temperature। |
| **Bias** | Data, measurement, sample বা model-এ থাকা ধারাবাহিক অসমতা, যা ফলকে একদিকে প্রভাবিত করতে পারে। |
| **Calibration** | Sensor-এর output-কে reference/পরিচিত standard-এর সঙ্গে মিলিয়ে পরিমাপের অর্থ নির্ধারণ বা সংশোধন। |
| **Collection / dataset** | একধরনের সংগঠিত data product বা সম্পর্কিত data-র সমষ্টি। Provider কীভাবে সংজ্ঞা দিয়েছে তা দেখুন। |
| **Coordinate** | কোনো স্থান চিহ্নিত করার সংখ্যাগত মান—যেমন latitude ও longitude। |
| **CRS (Coordinate Reference System)** | পৃথিবীর পৃষ্ঠে অবস্থান/আকৃতি কীভাবে মাপা ও মানচিত্রে দেখানো হয় তার reference system। |
| **Data** | পর্যবেক্ষণ, measurement, record বা model থেকে পাওয়া সংগঠিত তথ্য। |
| **Data granule** | Collection-এর একটি একক data item/file/segment; ঠিক কী বোঝায় তা archive অনুযায়ী বদলাতে পারে। |
| **Data lineage** | Data কোথা থেকে এসেছে এবং কোন processing-এর মধ্য দিয়ে গেছে তার ইতিহাস। |
| **Data product** | Sensor বা processing workflow থেকে প্রকাশিত নির্দিষ্ট measurement/derived data package। |
| **Dataset version** | Data বা processing-এর নির্দিষ্ট release; version বদলালে ফলও বদলাতে পারে। |
| **Derived data** | মূল data-কে filter, combine, convert বা calculate করে তৈরি output। |
| **Earth observation (EO)** | Satellite, aircraft, ground sensor বা অন্য উপায়ে পৃথিবী সম্পর্কে তথ্য সংগ্রহ/বিশ্লেষণ। |
| **Environmental data** | আবহাওয়া, জলবায়ু, land, ocean, ecosystem বা পরিবেশ-সম্পর্কিত measurement/record। |
| **Evidence** | Claim বা সিদ্ধান্ত সমর্থনে ব্যবহারযোগ্য পর্যবেক্ষণ, test result, data বা source। |
| **Granule** | Archive-এ কোনো collection-এর ছোট একক file/data item; metadata থেকে এর spatial/time coverage দেখুন। |
| **Ground truth** | কোনো measurement বা model ফল যাচাইয়ের জন্য ব্যবহার করা স্বাধীন reference observation/তথ্য। |
| **Metadata** | Data সম্পর্কে তথ্য: কে তৈরি করেছে, কী মাপা হয়েছে, কোথায়/কখন, unit, format, version ও ব্যবহার নির্দেশনা। |
| **Missing value / no-data** | কোনো record বা pixel-এ valid measurement নেই—এমন চিহ্ন; এটি সাধারণত শূন্যের সমান নয়। |
| **Model** | বাস্তব ব্যবস্থার সরল গাণিতিক/গণনামূলক বর্ণনা; model output পর্যবেক্ষণের সমান নয়। |
| **Observation** | Sensor বা পদ্ধতিতে পাওয়া বাস্তব measurement/দেখা ঘটনা। |
| **Open data** | নির্দিষ্ট terms অনুযায়ী public access বা reuse-যোগ্য data; “open” শব্দটি দেখে exact rights অনুমান করবেন না। |
| **Outlier** | অন্য observation থেকে অনেক আলাদা মান; এটি error, বিরল ঘটনা বা বাস্তব signal হতে পারে—যাচাই প্রয়োজন। |
| **Parameter** | Model, API, query বা calculation-এ নির্দিষ্ট করা input/setting। |
| **Pixel** | Raster image/grid-এর ক্ষুদ্র cell; satellite pixel একক বস্তু নয়, একাধিক surface-এর মিশ্র signal হতে পারে। |
| **Processing level** | Raw/calibrated/derived/gridded ইত্যাদি ধাপে data কতটা process হয়েছে তার label। |
| **Quality flag** | Measurement ব্যবহারের মান/বিশ্বাসযোগ্যতা বা কোনো caveat বোঝানো metadata value। |
| **Resolution (spatial)** | একটি pixel/measurement আনুমানিক কত জায়গা বোঝায় তার spatial detail। |
| **Resolution (temporal)** | Data কত ঘন ঘন বা কোন সময় ব্যবধানে observation দেয়। |
| **Sample** | মূল collection থেকে নেওয়া ছোট অংশ, অথবা পরীক্ষা/উদাহরণের data। Sample-কে পুরো population ভাববেন না। |
| **Sensor / instrument** | Data সংগ্রহ বা measurement করার যন্ত্র। |
| **NASA data** | NASA mission, program বা archive-সংশ্লিষ্ট data; source, access ও reuse terms নির্দিষ্ট collection অনুযায়ী যাচাই করতে হয়। |
| **Spatial coverage** | Dataset কোন ভৌগোলিক অঞ্চল কভার করে। |
| **Temporal coverage** | Dataset কোন সময়কাল কভার করে। |
| **Time series** | সময়ের ক্রমে সাজানো measurement বা data point। |
| **Uncertainty** | Measurement, estimate বা model result কতটা অনিশ্চিত—তার পরিমাপ/বর্ণনা। |
| **Unit** | Measurement-এর একক; যেমন metre, kelvin বা millimetre/day। |
| **Variable** | Dataset-এ মাপা বা গণনা করা quantity; যেমন surface temperature বা precipitation। |

## ৫. Mapping ও geospatial

| শব্দ | সহজ বাংলা ব্যাখ্যা |
|---|---|
| **Basemap** | Map-এর পটভূমি—যেমন coast, road, boundary বা terrain; এটি scientific data layer থেকে আলাদা হতে পারে। |
| **Bounding box** | কোনো search/download-এ ব্যবহৃত উত্তর-দক্ষিণ-পূর্ব-পশ্চিম সীমা দিয়ে বর্ণিত rectangular area। |
| **Feature (GIS)** | Vector map-এর point, line বা polygon এবং তার attribute। |
| **GeoJSON** | Geographic feature ও coordinate প্রকাশের JSON-ভিত্তিক format। |
| **GIS (Geographic Information System)** | ভৌগোলিক তথ্য সংরক্ষণ, বিশ্লেষণ ও মানচিত্রে দেখানোর software/workflow। |
| **Georeferencing** | Image/map/data-কে বাস্তব ভৌগোলিক অবস্থান ও coordinate system-এর সঙ্গে যুক্ত করা। |
| **Layer** | Map বা visualization-এ আলাদা data/imagery/feature-এর স্তর, যা অন্য layer-এর ওপর দেখানো যায়। |
| **Latitude** | নিরক্ষরেখার উত্তর বা দক্ষিণে অবস্থানের কৌণিক মাপ। |
| **Longitude** | Prime Meridian-এর পূর্ব বা পশ্চিমে অবস্থানের কৌণিক মাপ। |
| **Map projection** | পৃথিবীর বাঁকা পৃষ্ঠকে সমতল map-এ দেখানোর গাণিতিক পদ্ধতি; এতে কোনো না কোনো distortion হয়। |
| **OGC service** | Open Geospatial Consortium-এর নির্দিষ্ট standard অনুযায়ী geospatial data/service আদান-প্রদানের পদ্ধতি। |
| **Raster** | Grid/pixel আকারে রাখা spatial data; প্রতিটি cell-এ value থাকতে পারে। |
| **Reprojection** | Spatial data-কে এক CRS থেকে অন্য CRS-এ রূপান্তর। |
| **Scale** | Map-এর দূরত্ব ও বাস্তব দূরত্বের অনুপাত; scale বদলালে দেখা detail বদলায়। |
| **Tile** | বড় map/image-কে ছোট ছোট অংশে ভাগ করে web map-এ দেখানোর unit। |
| **Vector data** | Point, line, polygon এবং তাদের attribute দিয়ে spatial feature প্রকাশ। |

## ৬. Coding, software ও web

| শব্দ | সহজ বাংলা ব্যাখ্যা |
|---|---|
| **Accuracy** | কোনো measurement বা model output reference/বাস্তব মানের কতটা কাছাকাছি—তার মূল্যায়ন; spatial resolution বা confidence score-এর সমান নয়। |
| **Backend** | Server-side অংশ, যা data, logic, API বা database পরিচালনা করে। |
| **Bug** | Software-এর ভুল বা অপ্রত্যাশিত আচরণ। |
| **Cache** | আগের data/result সাময়িকভাবে রেখে পরে দ্রুত ব্যবহার করার ব্যবস্থা। |
| **Client-side** | User-এর browser বা device-এ চলা অংশ। Public JavaScript-এ secret রাখা নিরাপদ নয়। |
| **Code repository** | Code, history, documentation ও issue রাখার version-controlled জায়গা। |
| **Event** | নির্দিষ্ট তারিখ, সময় ও format-এ হওয়া আয়োজন; schedule ও deadline official event page-এ যাচাই করতে হয়। |
| **Commit** | Version control-এ change-গুলোর একটি সংরক্ষিত snapshot। |
| **CSS** | Web page-এর layout, colour, typography ও presentation নির্ধারণের stylesheet language। |
| **Database** | Data সংরক্ষণ ও query করার সংগঠিত ব্যবস্থা। |
| **Dependency** | Project যে package/library/service-এর ওপর নির্ভর করে। |
| **Deployment** | App বা service-কে user-এর ব্যবহারের জন্য server/hosting-এ প্রকাশ করা। |
| **Frontend** | User সরাসরি যে interface বা browser অংশ দেখেন ও ব্যবহার করেন। |
| **Framework** | App তৈরির কাঠামো, convention ও reusable component দেয় এমন software platform। |
| **Git** | Code change-এর history track, branch ও merge করার version-control system। |
| **HTML** | Web page-এর content ও structure বর্ণনার markup language। |
| **JSON** | Key-value ও list আকারে structured data প্রকাশের text format। |
| **Key (API key)** | কিছু API-তে request শনাক্ত/নিয়ন্ত্রণে ব্যবহৃত credential; password-এর মতো গোপন রাখতে হয়, যদি provider তাই বলে। |
| **Library** | নির্দিষ্ট কাজ সহজ করতে reusable function/code-এর সংগ্রহ। |
| **Notebook** | Code, text, table ও chart এক document-এ চালানো/দেখানোর interactive environment। |
| **Open-source software** | Open Source Definition-এর মানদণ্ড পূরণকারী licence-এর অধীনে ব্যবহার, পরিবর্তন ও বিতরণযোগ্য software। Exact licence পড়তে হয়। |
| **Package manager** | Software dependency install, version ও update পরিচালনার tool। |
| **Pull request / merge request** | এক branch-এর code change review ও অন্য branch-এ merge করার প্রস্তাব। |
| **Raster file** | Pixel/grid-এ মান থাকা geospatial বা image data file; format অনুযায়ী metadata থাকতে পারে। |
| **README** | Project কী, কীভাবে চালাতে/ব্যবহার করতে হয়, data/source কী—তা বোঝানো documentation file। |
| **REST API** | HTTP method ও URL-ভিত্তিক pattern-এ data/service request করার API style। |
| **Schema** | Data-এর field, type, structure ও constraint-এর বিবরণ। |
| **Static site** | Server-side application logic ছাড়াই প্রস্তুত HTML/CSS/JS file serve করা website। |
| **Test case** | নির্দিষ্ট input ও expected result দিয়ে feature যাচাইয়ের উদাহরণ। |
| **UI (User Interface)** | User যে control, screen, text ও visual element-এর সঙ্গে interaction করেন। |
| **UX (User Experience)** | কোনো product/service ব্যবহার করার সামগ্রিক অভিজ্ঞতা। |

## ৭. AI, model ও automation

| শব্দ | সহজ বাংলা ব্যাখ্যা |
|---|---|
| **AI (Artificial Intelligence)** | বিভিন্ন গণনামূলক পদ্ধতির বিস্তৃত নাম; নির্দিষ্ট model, tool ও policy আলাদা হতে পারে। |
| **AI-generated content** | AI tool দিয়ে তৈরি বা উল্লেখযোগ্যভাবে পরিবর্তিত text, image, audio, video বা code। |
| **Bias (model)** | Training data, labels, objective বা deployment context-এর কারণে model-এর output-এ ধারাবাহিক অসমতা। |
| **Classification** | Input-কে নির্ধারিত class/category-তে রাখা task। |
| **Confidence score** | Model কোনো output-এ কতটা confident দেখায় তার numerical score; এটি সঠিক হওয়ার নিশ্চয়তা নয়। |
| **Generative model** | Prompt/input থেকে নতুন text, image, audio, code বা অন্য output তৈরি করা model। |
| **Hallucination** | AI system-এর বিশ্বাসযোগ্য শোনালেও ভুল/উদ্ভাবিত তথ্য বা citation তৈরি করা। |
| **Human review** | মানুষ AI output, evidence, safety বা quality পরীক্ষা করে final সিদ্ধান্ত নেন। |
| **Inference** | Trained model-কে নতুন input দিয়ে output তৈরি করানো। |
| **Machine learning (ML)** | Data থেকে pattern শেখানো model তৈরির পদ্ধতি। |
| **Model evaluation** | নির্দিষ্ট test data ও metric দিয়ে model-এর ফল, error ও limitation পরীক্ষা। |
| **Prompt** | Generative AI-কে দেওয়া নির্দেশনা বা input। |
| **Synthetic data** | বাস্তব observation নয়; model, rule বা simulation দিয়ে তৈরি কৃত্রিম data। |
| **Training data** | Model শেখাতে ব্যবহৃত data। এর source, licence ও representativeness গুরুত্বপূর্ণ। |
| **Validation data** | Model/configuration যাচাই ও tuning-এ ব্যবহৃত data; test set-এর সঙ্গে ভূমিকা আলাদা হতে পারে। |
| **Test data** | Final model performance স্বাধীনভাবে মূল্যায়নের জন্য রাখা data। |

## ৮. Citation, licence ও submission

| শব্দ | সহজ বাংলা ব্যাখ্যা |
|---|---|
| **Apache License 2.0** | OSI-approved software licence; copyright, patent ও distribution-সংক্রান্ত নিজস্ব শর্ত আছে। Full licence ও NOTICE পড়ুন। |
| **Attribution** | Creator/provider-কে নির্দিষ্টভাবে credit দেওয়া। |
| **Copyright** | Original work-এর copy, adaptation, distribution ও display-সহ নির্দিষ্ট ব্যবহারে অধিকার নিয়ন্ত্রণকারী আইনগত ব্যবস্থা। |
| **Citation** | Data, code, publication, media বা claim-এর source শনাক্ত করার reference। |
| **Creative Commons (CC)** | Content licensing-এর একগুচ্ছ licence; BY, SA, NC, ND-এর শর্ত আলাদা। |
| **Derivative work** | আগের work-কে বদলে/রূপান্তর করে তৈরি নতুন কাজ—কোনটি derivative তা আইন/licence অনুযায়ী নির্ধারিত হতে পারে। |
| **EULA (End User License Agreement)** | Software বা data ব্যবহারকারীর জন্য নির্দিষ্ট licence/terms, যা ব্যবহার গ্রহণের আগে মানতে হতে পারে। |
| **Intellectual property (IP)** | Copyright, patent, trademark ও trade secret-এর মতো সৃষ্ট/আবিষ্কৃত বিষয়ের অধিকারসমূহের সাধারণ নাম। |
| **Licence** | কোনো resource কীভাবে ব্যবহার, পরিবর্তন বা বিতরণ করা যাবে তার শর্ত। |
| **MIT License** | বহুল ব্যবহৃত permissive software licence; copyright ও licence notice রাখার শর্ত থাকে। |
| **Notice file** | Project-এ ব্যবহৃত third-party component ও required legal/credit notice একত্রে রাখার file। |
| **OSI (Open Source Initiative)** | Open-source definition ও software licence review/approval-সংশ্লিষ্ট সংস্থা। |
| **Open Source Definition (OSD)** | OSI-এর মানদণ্ড, যা open-source software licence-এ কী ধরনের স্বাধীনতা/শর্ত থাকতে হবে তা বর্ণনা করে। |
| **Permission** | কোনো কাজ/asset ব্যবহার বা প্রকাশে অধিকারধারীর অনুমতি। Citation permission-এর বিকল্প নয়। |
| **Public domain** | নির্দিষ্ট jurisdiction-এ copyright protection নেই বা অধিকার ত্যাগ/মেয়াদোত্তীর্ণ—এমন কাজের অবস্থা; প্রতিটি দেশ/asset-এ একই নয়। |
| **Third-party material** | Team-এর তৈরি নয়—অন্য ব্যক্তি/সংস্থা/প্রকল্পের data, code, image, audio, font বা content। |
| **Trademark** | নাম, logo, mark বা sign যা কোনো সংস্থা/পণ্য/উৎস শনাক্ত করে; ব্যবহার আলাদা নিয়মে নিয়ন্ত্রিত হতে পারে। |
