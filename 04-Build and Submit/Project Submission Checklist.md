# Project Submission Checklist

## NASA Space Apps Challenge project জমা দেওয়ার আগে পূর্ণাঙ্গ যাচাই

> **এটি team-এর final review checklist—NASA-র official submission form বা কোনো নির্দিষ্ট বছরের required-field list নয়।** কোন field, file, video, link, format, size limit ও deadline প্রযোজ্য তা আপনার বছরের Project Submission Guide, event page এবং team project page থেকে নিন। এই তালিকায় যেটি “ঐচ্ছিক/যদি প্রযোজ্য” বলা আছে, official guide না চাইলে সেটিকে বাধ্যতামূলক ধরে নেবেন না।
>
> **২০২৬-এর যাচাইকৃত শর্ত:** ২০২৬ FAQ অনুযায়ী, Global Judging-এর জন্য team-কে official team project page দিয়ে project submit করতে হয়। ২০২৬ Participant Terms-এ ব্যবহৃত প্রত্যেকটি source cite, প্রযোজ্য third-party licence নথিভুক্ত এবং original/third-party content-এর অধিকার যাচাই করার কথা আছে। AI/SI tool ব্যবহার করলে ২০২৬ FAQ submission-এ তার ব্যবহার বর্ণনা করতে বলে। এগুলো ২০২৬-এর তথ্য; অন্য বছরের জন্য current FAQ, Terms ও guide দেখুন।

## ১. Final submission-এর আগে নিয়ম

এই ক্রমে official instruction যাচাই করুন:

1. অংশগ্রহণের বছরের Participant Terms and Conditions;
2. নির্বাচিত challenge-এর full Challenge Statement ও challenge-specific resource;
3. Project Submission Guide;
4. আপনার Local Event বা Universal Event-এর নির্দেশনা;
5. Judging & Awards Guide;
6. এই সহায়ক checklist।

Submission page বা guide-এর নির্দেশনা এই checklist-এর সাধারণ পরামর্শের চেয়ে অগ্রাধিকার পাবে। কোনো required field এখানে নেই—এমন হলেও official form-এ থাকলে পূরণ করতে হবে। আবার এই checklist-এ আছে—এমন কোনো item official guide না চাইলে NASA-র বাধ্যতামূলক item বলে উপস্থাপন করবেন না।

## ২. কে কী যাচাই করবেন?

কমপক্ষে দুজনের review রাখুন:

| দায়িত্ব | কী করবেন |
|---|---|
| **Submission owner** | Official project page/form-এ তথ্য পূরণ, প্রয়োজনীয় file/link যোগ ও final submit |
| **Independent checker** | Challenge fit, spelling, source/licence, link access, privacy, demo ও status যাচাই |
| **Team member/owners** | নিজের কাজ, নাম, অবদান ও ব্যবহৃত source সঠিক কি না নিশ্চিত |

ছোট দলে একই ব্যক্তি একাধিক দায়িত্ব নিতে পারেন; তবে সম্ভব হলে final form জমার আগে অন্য একজনকে দেখে নিতে বলুন।

## ৩. ব্যবহার-পদ্ধতি: Blocker / Required / Recommended

- **Blocker:** সমস্যা থাকলে জমা দেওয়ার আগে সমাধান করুন, scope কমান বা official clarification নিন।
- **Required by current guide:** আপনার বছরের official guide-এ চাওয়া থাকলে অবশ্যই সম্পূর্ণ করুন।
- **Recommended:** ভালো review practice; NASA-র বাধ্যতামূলক requirement নয়, যদি official guide আলাদা করে না বলে।

প্রতিটি item-এর পাশে status লিখুন: `Done`, `Not applicable`, `Blocked`, বা `Needs clarification`। “Not applicable” হলে সংক্ষিপ্ত কারণ লিখে রাখুন।

## ৪. A. Official event ও deadline

- [ ] **Required by current guide:** সঠিক বছরের event page-এ নিবন্ধিত আছি।
- [ ] **Required by current guide:** সঠিক team page, challenge এবং Local Event/Universal Event নির্বাচন করা আছে।
- [ ] Event-এর official start, end এবং submission deadline নোট করেছি।
- [ ] Deadline-এর timezone মিলিয়ে calendar-এ reminder দিয়েছি।
- [ ] Submission window বা edit/re-submit করার নিয়ম current guide থেকে যাচাই করেছি।
- [ ] Local Lead বা event-specific instruction-এ আলাদা deadline/প্রক্রিয়া থাকলে তা অনুসরণ করেছি।
- [ ] Deadline-এর আগে final review ও upload-এর জন্য buffer রেখেছি।
- [ ] Team member-দের নাম/অংশগ্রহণের status সঠিক কি না project page-এ যাচাই করেছি।

**Status:** `Done / Not applicable / Blocked / Needs clarification`

## ৫. B. Challenge requirement ও project fit

- [ ] নির্বাচিত Challenge-এর full statement পড়েছি; শুধু title/summary নয়।
- [ ] Project-টি কোন challenge address করছে তা project description-এ স্পষ্ট।
- [ ] Solution challenge-এর মূল problem বা user need-এর সঙ্গে সরাসরি যুক্ত।
- [ ] Statement-এর required output/feature/constraint বর্তমান prototype-এ পূরণ হয়েছে, অথবা অসম্পূর্ণ অংশ সত্যভাবে বলা হয়েছে।
- [ ] Project-এর core capability এক-দুই বাক্যে বোঝানো যায়।
- [ ] Demo-তে project কীভাবে কাজ করে, তা দেখা যায়; শুধু future plan দেখানো হচ্ছে না।
- [ ] Project-এর audience/user স্পষ্ট, যদি challenge-এর জন্য প্রযোজ্য হয়।
- [ ] যা তৈরি হয়নি, তা completed feature বলে দাবি করা হয়নি।
- [ ] Challenge statement-এর বাইরে নিজেরা যে assumption নিয়েছি, তা নথিবদ্ধ করেছি।

**Blocker:** Project যদি নির্বাচিত challenge-এর সঙ্গে বাস্তবভাবে না মেলে, description বদলানো নয়—সমাধানের scope ও challenge fit আবার পর্যালোচনা করুন।

## ৬. C. Project content ও factual accuracy

- [ ] Project name/title অর্থবহ, সংক্ষিপ্ত এবং বিভ্রান্তিকর নয়।
- [ ] Summary-তে problem, solution ও intended benefit স্পষ্ট।
- [ ] Description-এ project কীভাবে কাজ করে তা বলা আছে।
- [ ] Data, method, model বা calculation গুরুত্বপূর্ণ হলে তার সংক্ষিপ্ত ব্যাখ্যা আছে।
- [ ] Scientific/technical claim ব্যবহৃত evidence দিয়ে সমর্থিত।
- [ ] Correlation-কে causation বা model output-কে নিশ্চিত বাস্তব ফল বলা হয়নি।
- [ ] Data sample/synthetic/mock হলে তা স্পষ্টভাবে label করা হয়েছে।
- [ ] সীমাবদ্ধতা, uncertainty, assumption ও অসম্পূর্ণ feature গোপন করা হয়নি।
- [ ] Unit, date range, location, legend, axis এবং colour scale প্রয়োজনমতো label করা।
- [ ] Project-এর spelling, grammar, link text, caption ও acronym review হয়েছে।
- [ ] Project-এ অনুপযুক্ত, হয়রানিমূলক, বৈষম্যমূলক, হুমকিমূলক বা আইনবিরুদ্ধ content নেই।
- [ ] Project-কে NASA-র endorsement/official product বলে ভুল বোঝায়—এমন দাবি বা presentation নেই।

**Recommended:** একজন team member যিনি মূল feature লেখেননি, তাকে project description পড়তে দিন। তিনি কি বুঝতে পারছেন project কী করে এবং কী করে না?

## ৭. D. Data source ও citation

### Source completeness

- [ ] ব্যবহৃত সব dataset, API, code/library, image, audio, video, map tile, font, icon, paper, model ও external asset-এর তালিকা করেছি।
- [ ] প্রত্যেক source-এর provider/creator ও official landing page/DOI/URL আছে।
- [ ] Dataset হলে collection/product name, version/date range ও ব্যবহৃত subset যতটা সম্ভব উল্লেখ করেছি।
- [ ] API হলে API/endpoint documentation, accessed date এবং প্রাসঙ্গিক data/product উল্লেখ করেছি।
- [ ] Media হলে asset page-এ থাকা credit/creator/ID ব্যবহার করেছি।
- [ ] Source list-এর entry actual project-এর সঙ্গে মিলিয়ে দেখেছি; ব্যবহৃত কিছু বাদ নেই।
- [ ] Open-source বা no-cost resource-ও citation list-এ আছে।
- [ ] Current-year submission form-এ citation/reference field থাকলে সব relevant source সেখানে দিয়েছি।

**২০২৬ Terms:** ২০২৬ Participant Terms সব ব্যবহৃত source cite করতে বলে—open-source বা বিনামূল্যের source-ও অন্তর্ভুক্ত। পরবর্তী বছরের Terms-এ একই শর্ত আছে কি না পুনরায় যাচাই করুন।

### Citation template

Provider-এর recommended citation থাকলে সেটি অগ্রাধিকার দিন। তা না থাকলে উপযুক্ত তথ্যসহ এই template ব্যবহার করুন:

```text
Provider/Creator. (Release year/date). Dataset/asset title,
collection/product/version (যদি থাকে), mission/instrument (প্রযোজ্য হলে),
সময়কাল/স্থান। DOI বা official URL. Accessed: YYYY-MM-DD.
Licence/attribution note: provider-এর নির্দেশনা অনুযায়ী।
```

## ৮. E. Licence, permission ও intellectual property

- [ ] নিজের team-এর তৈরি content এবং third-party material আলাদা করে শনাক্ত করেছি।
- [ ] Code, dataset, image, audio, font, map, model ও documentation-এর applicable licence/terms পড়েছি।
- [ ] Asset ব্যবহার, modify, redistribute বা public submission-এ দেখানোর অধিকার আছে কি না যাচাই করেছি।
- [ ] Third-party licence/attribution requirement source register বা project documentation-এ রেখেছি।
- [ ] Required permission বা licence documentation সংযুক্ত/উল্লেখ করেছি, যদি current guide চায়।
- [ ] “Google-এ পেয়েছি”, “public page-এ আছে” বা “free download”—এগুলোকে reuse permission ধরে নিইনি।
- [ ] NASA website-এর third-party credited content আলাদা করে যাচাই করেছি।
- [ ] NASA insignia/logotype/emblem এমনভাবে ব্যবহার করিনি যাতে official endorsement বোঝায়।
- [ ] Identifiable ব্যক্তি, বিশেষ করে minor, media-তে থাকলে current Terms, consent ও privacy requirement যাচাই করেছি।
- [ ] Team-এর original content কোন licence-এ যাবে তা current Participant Terms অনুযায়ী বুঝেছি।
- [ ] এমন কোনো confidential, business-sensitive বা অন্যের মালিকানাধীন তথ্য নেই যা প্রকাশের অধিকার আমাদের নেই।

**২০২৬ Space Apps Terms:** original solution-এর প্রকাশ/ব্যবহার ও open-source licensing নিয়ে Terms-এ নির্দিষ্ট শর্ত আছে; নির্দিষ্ট OSI-compliant licence না দিলে Apache 2.0-এ বিতরণের কথা বলা হয়েছে। Third-party material-এর উপযুক্ত public availability/licence এবং documentation-ও team-এর দায়িত্ব। Submission-এর আগে [বর্তমান Terms](https://www.spaceappschallenge.org/legal/) সম্পূর্ণ পড়ে নিন। এটি আইনি পরামর্শ নয়।

## ৯. F. Code, repository ও technical access

যদি project-এ code বা software থাকে:

- [ ] Repository/demo URL সঠিক এবং project-এর সঙ্গে সম্পর্কিত।
- [ ] Reviewer/সাধারণ user link খুলতে পারবেন—permission বাস্তবে পরীক্ষা করেছি।
- [ ] Setup/run instructions পরিষ্কার, সংক্ষিপ্ত ও পরীক্ষা করা।
- [ ] প্রয়োজনীয় runtime, dependency বা version উল্লেখ আছে—যদি প্রাসঙ্গিক হয়।
- [ ] `README`/project documentation-এ project purpose, data source, run/use instruction ও known limitation আছে—যদি ব্যবহারকারীর প্রয়োজন হয়।
- [ ] Repository-তে `.env`, password, private key, token, recovery code বা secret নেই।
- [ ] Private data, accidental file, debug dump বা অপ্রয়োজনীয় large file নেই।
- [ ] API key server-side/secret storage-এ আছে; public client bundle, source, screenshot বা submission text-এ প্রকাশিত নয়।
- [ ] API/service failure-এর fallback বা demo mode থাকলে তা স্পষ্ট।
- [ ] Dependency/asset-এর licence ও attribution current Terms অনুযায়ী রেকর্ড করা।
- [ ] Linkটি অন্য account/device/private window থেকে খোলা যায়—যদি public access প্রয়োজন হয়।

**যদি credential accidentally public হয়ে থাকে:** শুধু file থেকে মুছে দিলেই যথেষ্ট নাও হতে পারে। সংশ্লিষ্ট key revoke/rotate করুন এবং repository history-তে secret রয়ে গেছে কি না পরীক্ষা করুন।

## ১০. G. Demo, video ও media

Official Project Submission Guide-এ যেসব media চাওয়া হয়েছে কেবল সেগুলোই required হিসেবে ধরুন। নিচেরটি final review checklist:

- [ ] Demo/video/screenshot current guide-এর format, duration, size ও upload requirement মেনে চলে।
- [ ] Demo-তে মূল user journey বা project-এর central output দেখা যায়।
- [ ] Presenter/project description যা বলছে, demo তা সত্যিই দেখায়।
- [ ] Interface, map, chart, caption ও audio/visual যথেষ্ট স্পষ্ট।
- [ ] Demo-তে ব্যবহার করা sample/mock data সঠিকভাবে label করা।
- [ ] External API বা internet ব্যর্থ হলে fallback প্রস্তুত।
- [ ] Video/link public বা reviewer-accessible; account login প্রয়োজন হলে তা guide-এ অনুমোদিত/ব্যাখ্যাত।
- [ ] Video/audio/image-তে ব্যবহৃত সব third-party asset-এর reuse right ও credit যাচাই।
- [ ] ব্যক্তির ছবি, কণ্ঠ বা likeness ব্যবহারে প্রয়োজনীয় consent আছে।
- [ ] Minor-এর recognizable name, voice, image বা likeness current Terms অনুসারে বাদ/সুরক্ষিত।
- [ ] Media বা project-এ NASA employee/astronaut বা NASA logo এমনভাবে দেখানো হয়নি যাতে commercial endorsement বোঝায়।
- [ ] Caption/subtitle বা transcript প্রযোজ্য হলে যাচাই করা হয়েছে।

**Recommended:** final video-টি upload হওয়া platform থেকেই চালিয়ে দেখুন। Editing preview-তে চলা আর জমা দেওয়া link-এ চলা এক নয়।

## ১১. H. Form ও project page

এই section-এ কোনো নির্দিষ্ট form field বাধ্যতামূলক বলে দাবি করা হচ্ছে না। Current Project Submission Guide ও live team project page-কে অনুসরণ করে পূরণ করুন।

- [ ] সঠিক team project page খুলেছি; ভুল team বা event নয়।
- [ ] Challenge ও event affiliation সঠিক।
- [ ] Current form-এর সব required field পূরণ।
- [ ] প্রতিটি prompt-এর উত্তর সেই prompt-এর উদ্দেশ্য অনুযায়ী।
- [ ] Project description, link, citation, media ও disclosure যেখানে চাওয়া হয়েছে সেখানে যুক্ত।
- [ ] Character/word/file size limit থাকলে মেনেছি।
- [ ] Link/attachment-এ spelling, access permission ও target পরীক্ষা করেছি।
- [ ] Form-এর preview বা saved draft review করেছি।
- [ ] Team name, member list, project title ও public contact detail সঠিক; অপ্রয়োজনীয় personal info নেই।
- [ ] AI/SI disclosure current year-এর rules চাইলে সঠিকভাবে দিয়েছি।
- [ ] Form-এর final terms/consent পড়ে বুঝে তারপর সম্মতি দিয়েছি।

## ১২. I. AI/SI ও generated content disclosure

AI/SI বা generative tool ব্যবহার করে থাকলে:

- [ ] Current-year FAQ/Terms/Submission Guide-এ tool-use rules দেখেছি।
- [ ] Tool-এর ব্যবহার কী ছিল (research aid, coding, text/image/audio, translation, analysis) লিখেছি—যদি disclosure চাওয়া হয়।
- [ ] Generated factual claim, citation, code ও scientific explanation স্বাধীনভাবে যাচাই করেছি।
- [ ] Tool বানানো ভুল/কল্পিত source বা dataset সরিয়েছি।
- [ ] Generated/third-party asset-এর licence/terms ও attribution যাচাই করেছি।
- [ ] ব্যক্তিগত, confidential বা restricted data tool-এ দিইনি।
- [ ] Team-এর নিজস্ব কাজ ও tool-generated contribution গুলিয়ে ফেলিনি।

**২০২৬ FAQ:** AI-ধরনের tool ব্যবহারের অনুমতি এবং submission-এ কীভাবে ব্যবহার হয়েছে তা বর্ণনার কথা ২০২৬ FAQ-তে আছে। অন্য বছরের জন্য এই নিয়ম নিজে থেকে ধরে নেবেন না।

## ১৩. J. Privacy, safety ও conduct

- [ ] ব্যক্তিগতভাবে শনাক্তযোগ্য তথ্য—যেমন home address, private phone, birth date, account credential—project/media-তে নেই।
- [ ] Public repository-তে sensitive data বা credential নেই।
- [ ] কোনো team member বা third party-র ব্যক্তিগত তথ্য/ছবি অনুমতি ছাড়া প্রকাশ করা হয়নি।
- [ ] Minor-এর media ও supervision-সংক্রান্ত current instruction মানা হয়েছে।
- [ ] Project content-এ threat, harassment, bullying, hate/discriminatory content বা আইনবিরুদ্ধ উপাদান নেই।
- [ ] Data interpretation থেকে অযথা medical, emergency, legal বা নিশ্চিত forecast দাবি করা হয়নি।
- [ ] Project-এর safety limitation থাকলে user-facing note দেওয়া হয়েছে।

## ১৪. K. Final demo / reviewer walkthrough

একজন team member project চালিয়ে দেখান:

1. Project link/file কোথা থেকে খুলবেন?
2. কোন input/sample ব্যবহার করবেন?
3. Core feature কীভাবে দেখাবেন?
4. Expected result কী?
5. Data/source কোথায় দেখানো আছে?
6. Limitation বা mock data কোথায় উল্লেখ?
7. Network/API বন্ধ হলে কী fallback?

- [ ] Team-এর অন্তত দুইজন walkthrough করতে পারেন, যদি সম্ভব হয়।
- [ ] Demo path-এর বাইরে থাকা feature-কে completed বলে দাবি করা হয়নি।
- [ ] Reviewer-এর জন্য কোনো hidden credential বা undocumented setup দরকার নেই।
- [ ] Submission link live অবস্থায় কাজ করছে।

## ১৫. L. Deadline-এর আগে final sign-off

| Reviewer | দায়িত্ব | নাম/initial | সময় | মন্তব্য |
|---|---|---|---|---|
| Submission owner | Form ও final submission | | | |
| Independent checker | Requirement, source, licence ও link | | | |
| Demo owner | Demo/media ও fallback | | | |
| Team representative | Member/credit ও consent | | | |

### Final status

- [ ] Current official deadline ও timezone আবার যাচাই।
- [ ] Submission guide-এর required field/file/link পূর্ণ।
- [ ] Final review-এর পরে ভুল link/file/description নেই।
- [ ] Submit/finalize action সম্পন্ন।
- [ ] Project page বা confirmation-এ submitted/final status দেখা।
- [ ] Confirmation বা final URL team-এর নিরাপদ record-এ সংরক্ষণ।
- [ ] আর edit করা যাবে কি না, current guide থেকে জানা।
- [ ] Deadline পার হওয়ার আগে অন্য team member-কে final status জানিয়েছি।

## ১৭. Frequently missed checks

- Form save হয়েছে, কিন্তু final submit করা হয়নি।
- Link কাজ করে, কিন্তু reviewer-এর permission নেই।
- Demo-র data mock, কিন্তু mock বলে লেখা হয়নি।
- Screenshot-এ API key বা personal information রয়ে গেছে।
- Dataset citation আছে, কিন্তু version বা date range নেই।
- NASA page-এর image-এ third-party credit ছিল, সেটি project-এ বাদ গেছে।
- Project description-এ এমন feature বলা হয়েছে যা demo-তে নেই।
- Team page-এ member বা challenge ভুল।
- Local time ও official deadline-এর timezone এক নয়।
- Current guide প্রকাশের পরে form বা rules update হয়েছে।
